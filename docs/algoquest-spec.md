## 1. コンセプトと設計方針

**一言で**: かわいいロボット「アルゴくん」が2Dフィールドを動き回り、変数に値を運んで入れたりしながら、基本情報技術者試験・科目Bの雰囲気のアルゴリズム問題（処理の追跡）を4択で解くブラウザパズルゲーム。

### 設計方針（迷ったらこれに従う）
1. **学習が主役**。演出は「処理の順序・値の変化を正しく伝える」ためにあり、派手さより正確さを優先する。
2. **詰まらせない**。コインやログインがなくても、全ステージと解説は無料で遊べる。
3. **ビルド不要・依存ゼロ**。HTML / CSS / JavaScript（ES Modules）のみ。npm・バンドラ・外部CDN・外部フォントに依存しない。GitHub Pages にそのまま置けること。
4. **問題はすべてオリジナル**。実際の試験問題・疑似言語の文面を転載しない（記法のスタイルを参考にするのみ）。
5. **ジャンルごとに難易度が段階的**。どのジャンルも「入門→試験レベル」まで用意し、全部が簡単・全部が難しい、にならないようにする（§10）。
6. **キャラクター以外はコード描画**。マップ・アイテム・変数ボックス・エフェクトはすべてCanvas/CSSで描く。

## 3. ゲームの基本ループ

1. **ステージ一覧**でジャンルとレベルを選ぶ
2. **問題画面**：フィールド（初期状態）・疑似コード・問題文・4択を見る（表示形式は日本語/疑似コードを切替可能）
3. 選択肢を1つ選び「こたえる」を押す
4. **選んだ選択肢のとおりにアルゴくんが動く**（値を運んでボックスに入れる等）
   - **正解**：動きが成功 → 「ピンポン」＋画面全体に○ → コイン/星 → 解説画面へ
   - **誤答**：動きの途中で作業に失敗 → 「ぶっぶー」＋画面全体に× →「何を見直すか」を表示 → その選択肢をグレーアウトして再挑戦（ヒント購入可）
5. （動きは**2倍速**・**スキップ**が選べる）
6. **解説画面**：正解の理由、行ごとの処理追跡、疑似コード、この問題のポイント
7. 「次のステージへ」「もう一度実演を見る」「一覧へ」

## 4. 画面仕様

画面は**単一HTML内のセクション切替**（SPA、`show(screenId)` 程度の自前ルーター）。

### 4.1 タイトル画面
- ロゴ「アルゴクエスト」（仮）、**立ち絵**（ゆっくり上下に揺れる）。背景はコード描画（パステルのグラデーション＋ふわふわ浮かぶ数字・記号の粒）。
- ボタン：「ゲームかいし」（セーブなし、または `tutorialSeen:false` のとき）／「つづきから」（セーブあり）、「あそびかた」、「せってい」
- **最初のタップで `AudioContext` を開始**（ブラウザの自動再生制限対策。§7.5）。
- 「ゲームかいし」を押すと **あいさつ＋遊び方案内（§4.1b）→ ステージ一覧** へ進む。「つづきから」は案内を飛ばして一覧へ。

### 4.1b あいさつと遊び方案内（`screens/tutorial.js`）
- 全画面。**アルゴくん（立ち絵）を大きく表示**し、吹き出しにセリフを**1文字ずつ**表示（タップで全文表示→もう一度タップで次へ）。セリフはひらがな多めで、やさしい口調。
- 各ページにアルゴくんの軽いリアクション（あいさつ＝小ジャンプ、説明＝ふわふわ、まとめ＝cheer）をコード演出で付ける。
- 右上に常に **「スキップ」**、下に「つぎへ」「もどる」。キーボード Enter / ← →。

| ページ | 内容（セリフは意味を保てば調整可） |
|---|---|
| 1 あいさつ | 「はじめまして！ ぼくは アルゴくん。いっしょに アルゴリズムを たんけんしよう！」 |
| 2 ゲームの目的 | 「しょりを よく よんで、ぼくが どうなるか、へんすうが いくつに なるかを 4つの なかから えらんでね」 |
| 3 画面の見かた | 小さなデモ画面を表示し、**左＝フィールド、右＝しょりと こたえ**をスポットライトで順に強調 |
| 4 へんすう | **変数ボックス**を紹介。「x ← 5」を自動再生し、「ぼくが 5を はこんで ボックスに いれるよ」と実演（§6のデモ） |
| 5 にほんご／ぎじコード | 切替トグルを強調。「どっちも おなじ しょり。すきな ほうで よんでね」 |
| 6 こたえたあと | 「えらんだ こたえどおりに ぼくが うごくよ。あってたら ○ と ピンポン！ ちがってたら × と ぶっぶー！ なんどでも ちょうせんできるよ」＋ **2倍速／スキップ**ボタンの場所を強調 |
| 7 コインとヒント | 「こまったら ヒントを つかえるよ。コインが なくても ちゃんと すすめるから あんしんしてね。じゃあ、いこう！」→ステージ一覧へ |

- 最後まで見る、またはスキップした時点で `tutorialSeen = true` を保存。
- 「あそびかた」ボタン（タイトル・設定）からいつでも再閲覧できる。
- ページ定義（セリフ・強調対象・デモ種別）は配列データとして持ち、コードに直書きしない。

### 4.2 ステージ一覧
- **ジャンルごとのセクション**（1ジャンル=1行の横並びカード5枚。スマホでは横スクロールまたは2列グリッド）
- ジャンル見出し：「①じゅんじょと へんすう」等＋ジャンル内の星合計
- カード：レベル表示（Lv1〜Lv5、難易度を★や色で表示：入門=緑、かんたん=水、ふつう=黄、ややむず=橙、むずかしい=赤）、タイトル、獲得星、状態（🔒/挑戦可/クリア済）
- ヘッダー：コイン残高、設定、戻る
- 未解放カードはタップすると軽く揺れるだけ

### 4.3 問題画面（PC：幅 ≥ 900px）

```
┌─────────────────────────────┬──────────────────────────────┐
│ ヘッダー：ステージ名／コイン／ヒント／戻る                          │
├─────────────────────────────┼──────────────────────────────┤
│                             │ [日本語 | 疑似コード] ←表示切替       │
│   フィールド（Canvas）        │ ─ 処理（行番号付き）────────       │
│   アルゴくんが動く            │  1  …                         │
│   変数ボックス・アイテム       │  2  …（実行中の行はハイライト）   │
│                             │ ─ 問題文 ────────────────      │
│   （左半分）                 │ ─ 4択（同じ表示形式で表示）─       │
│                             │  A. …   B. …   C. …   D. …    │
│                             │          [こたえる]             │
└─────────────────────────────┴──────────────────────────────┘
```

- 画面を**左右ちょうど半分**に分割（`grid-template-columns: 1fr 1fr`）。左がフィールド、右が処理＋問題＋選択肢。
- **表示切替トグル**（右パネル上部、常に見える位置）：
  - 「**日本語**」：処理・選択肢を日本語の文章で表示（例：`x に 5 を入れる`）
  - 「**疑似コード**」：処理・選択肢を疑似コード記法で表示（例：`x ← 5`）
  - 切替は**処理パネルと4択の両方に同時に適用**。選択状態・回答状態は切替で失われない。
  - 実演中でも切替可能（ハイライト行は維持）。
  - 選択は `settings.codeView`（`"ja"` / `"code"`）として保存し、次回以降の初期値にする。**初期値は `"ja"`**。
- 変数の現在値はフィールド上の**変数ボックス**に表示される（§6）。さらに、フィールド下に小さな「変数一覧バー」も出す（一目で値が見えるように。ボックスと同じ色）。
- フィールド領域が余る場合は縦中央寄せ。フィールドは常にアスペクト比維持で拡大縮小（`devicePixelRatio` 対応）。

### 4.4 問題画面（スマホ縦：幅 < 900px）
上から順に縦積み：
1. ヘッダー（コンパクト）
2. フィールド（画面幅いっぱい、高さは画面の約40%まで）
3. 変数一覧バー
4. **表示切替トグル**（日本語/疑似コード）
5. 処理（行番号付き。行数が多い場合は最大高さ＋内部スクロール、実演中は実行行へ自動スクロール）
6. 問題文
7. 4択（縦並び、各48px以上）
8. 「こたえる」ボタン（画面下に固定表示してよい）

フィールドは**実演中のみ画面上部に固定（sticky）**して、スクロールしても動きを見られるようにする。

### 4.5 結果表示（回答後の流れ）
1. 「こたえる」を押す → **選んだ選択肢のとおりにアルゴくんが動く**（§7.3）。
2. **正解**：動きが最後まで成功 → 効果音「ピンポン」＋**画面全体に大きな ○**（アルゴくんは cheer）→ 獲得コイン・星を表示 → 解説画面へ。
3. **誤答**：動きの途中で**作業に失敗**（`fail`。アルゴくんは confused）→ 効果音「ぶっぶー」＋**画面全体に大きな ×** → `wrongFeedback` を表示 → 盤面を初期状態に戻して再挑戦。

**○×オーバーレイ**
- 画面全体に半透明の膜をかけ、中央に巨大な ○ または ×（Canvas/CSSのコード描画。太い線で描き込まれるアニメ）。
- 配色は日本のクイズ番組風：○＝赤系 `#E53935`、×＝青系 `#1E66F5`。形でも区別できる（色に依存しない）。
- 約0.9秒で自動フェードアウト、タップで即閉じ可。**○×の表示と効果音は同時に開始**。
- `prefers-reduced-motion` 時は拡大・描き込みなしでフェードのみ。

### 4.6 解説画面
- 正解と理由（`explanation.why`）
- **処理の追跡表**：行ごとに「実行した行」「その時点の変数・位置」（`explanation.trace`）
- 疑似コード全文（トグルで日本語/疑似コード切替、追跡表の行をタップで該当行ハイライト）
- 「この問題のポイント」（`explanation.points`）
- 「もう一度実演を見る」ボタン（コイン消費なし）
- 欄名：**「処理の解説」「疑似コード」「この問題のポイント」**
- PCでも左右分割：左＝フィールド（再実演）、右＝解説

### 4.7 設定画面
- 「実演を常に2倍速にする」ON/OFF（既定OFF。実演中にも切替可、§7.4）
- 効果音 ON/OFF と音量（既定ON・音量0.7）
- 「あそびかた」をもう一度見る（§4.1b）
- 初期の表示形式（日本語/疑似コード）
- 「アニメーションを減らす」（`prefers-reduced-motion` を初期値に反映）
- セーブデータ削除（確認ダイアログ付き）

## 5. キャラクター「アルゴくん」（提供画像を使用）

### 5.1 使用画像
| ファイル（置き場所） | 用途 |
|---|---|
| `assets/img/algokun_stand.png` | **立ち絵**：待機、タイトル、アイテムを待つとき、クリア時、解説画面など「動いていない」全場面 |
| `assets/img/algokun_move.png` | **移動絵**：マスを移動している間（および「運んでいる」間） |

- 絵柄：白と青のボディ、オレンジのアンテナ先、黒い顔画面に水色の目、ドット絵（ピクセルアート）。
- ファイル名は上記で固定。Claude Codeはユーザー提供の2枚をこの名前で配置する前提で実装する。
- **背景透過の確認（必須）**：読み込み後、画像の四隅が透明か確認する。**チェッカー柄（透明表現の市松模様）が背景に焼き込まれている場合**は、Pythonスクリプト（`tools/remove-bg.py`、PIL使用、外周から塗りつぶしで市松の白/灰を透明化）で透過PNGにして上書き保存し、その旨を `DECISIONS.md` に記録する。元画像は `assets/img/original/` に保管。
- 描画は必ず `ctx.imageSmoothingEnabled = false`（ドット絵をにじませない）。CSSで表示する場合は `image-rendering: pixelated`。
- 余白の違いで位置がずれないよう、読み込み時に透明部分を除いた**バウンディングボックスを算出し、足元基準で描画位置を揃える**（立ち絵と移動絵を切り替えてもジャンプしない）。表示サイズはタイル1枚の約1.0〜1.2倍（頭のアンテナがはみ出して良い）。

### 5.2 状態と描画ルール
| 状態 | 絵 | コード描画の演出 |
|---|---|---|
| `idle`（待機） | 立ち絵 | ゆっくり上下に±2px程度のふわふわ、数秒おきに軽く傾く |
| `move`（移動） | **移動絵** | **移動中、移動絵を上下に軽く揺らす**（下記） |
| `hold`（値を持つ） | 立ち絵 | 頭上または体の前に**値クリスタル**（数字入り）をコード描画で表示 |
| `carry`（運ぶ） | 移動絵 | 移動絵＋頭上にクリスタルを表示し、一緒に揺れる |
| `store`（ボックスに入れる） | 立ち絵 | クリスタルが縮みながらボックスに吸い込まれる（§6） |
| `think`（考え中） | 立ち絵 | 頭上に「…」の吹き出し（コード描画） |
| `cheer`（正解） | 立ち絵 | 2回ジャンプ＋星/キラキラのパーティクル |
| `confused`（誤答） | 立ち絵 | 左右に小さく揺れる＋頭上に「？」＋汗マーク |

### 5.3 移動時の上下揺れ（仕様）
- 1マス移動 ＝ タイル間を線形補間で移動（`moveDuration` は基本700ms、2倍速で350ms）。
- 移動中、**移動絵のY座標に `sin` カーブでバウンドを加える**：振幅 約 タイル高さの6〜8%、1マスあたり**2回バウンド**。
- 横向き：進行方向が**左**のときは移動絵を**水平反転**（絵は右向きを基準とする。実際の向きが逆なら反転ロジックを逆にして `DECISIONS.md` に記録）。上下移動は反転せず、同じバウンドで移動。
- 移動絵⇄立ち絵の切替はステップ間で瞬時に行い、足元基準でズレないこと（§5.1）。
- `prefers-reduced-motion` 有効時：バウンド振幅を0にし、移動は短いフェードで表現。

## 6. 変数・値の更新の視覚表現（アルゴくんが持ってきて入れる）

**原則：変数の値が変わるときは、必ずアルゴくんが値を持ってきて、変数ボックスに入れ、中身が入れ替わる。** 変数パネルだけが勝手に書き換わることは禁止（演出なしにする場合は、解説画面の再実演でも同じ原則で動かす）。

### 6.1 フィールド上の部品（すべてコード描画）
- **変数ボックス**：フィールド上に置く箱（宝箱/貯金箱風）。ラベルに変数名、中に現在の値を表示。`varColors` で変数ごとに色分け（x=水色、y=緑、z=ピンク、配列=橙）。
- **値クリスタル**：数字が書かれた小さな多面体のアイテム。拾う→持つ→入れる、が見た目で分かること。
- **計算台**（`calcPad`）：式を計算するためのフィールド上の台（足し算・引き算などの結果を作る場所）。

### 6.2 基本パターン

**① 単純代入 `x ← 5`**
1. フィールドに「5」のクリスタルが出現（`spawnItem`）
2. アルゴくんがそこへ歩いて拾う（`pickup`、立ち絵に切替→クリスタルを頭上に）
3. `carry`：移動絵でボックス x まで運ぶ
4. `store`：クリスタルがボックスに吸い込まれる。**古い値があれば先にポンと外に飛び出して消える**
5. ボックスの値が `5` に更新され、ボックスが一瞬光る

**② 式を使う代入 `y ← x + 2`**
1. アルゴくんがボックス x へ行き、**値のコピーを取り出す**（x のボックスの中身は変わらない、コピークリスタルが出る）
2. 計算台まで運んで置く
3. 「+2」のクリスタルが出る（またはもう1回取りに行く）→ 計算台で**合体して結果クリスタルになる**（`calc`）
4. 結果クリスタルを持って、ボックス y まで運び、`store`
5. y の値が更新される

**③ 自分自身の更新 `x ← x + 1`**
上記②と同じ。入れる先が元のボックス x で、**古い値が外に出て消え、新しい値が入る**ことを見せる。

**④ 変数どうしの比較（条件）**
- アルゴくんが各ボックスからコピーを取り出し、**比較台**（`comparePad`）に並べて置く。判定結果（真/偽）がランプで光る（緑/赤）。→ 分岐先へ歩く。

**⑤ 配列への格納 `a[i] ← v`**
- フィールド上に**配列のマス列**（横並びのセル、添字付き）を置く。値クリスタルを運び、**指定の添字のセル**に入れる。**交換**は一時置き場（`tmp`ボックス）を使って「Aを取り出す→tmpへ→BをAへ→tmpの値をBへ」と1つずつ運ぶ。

**⑥ 繰り返しの変数 `i` の更新**
- ループごとに `i` のボックスが+1される演出を毎回見せる（遅い設定でも長すぎないよう、同じループ2周目以降は**自動で短縮**）。

### 6.3 ルール
- **処理順序が誤解されないこと**を最優先。1つの代入が終わってから次の行に進む。
- 疑似コードの現在行は演出と**必ず同期**してハイライト。
- 演出が長くなる問題（ループ・配列）でも、実演中の **[⏩ 2倍速] [⏭ スキップ]** で待ち時間を減らせる（§7.4）。
- 変数ボックスの色は、問題画面の「変数一覧バー」・解説の追跡表と**同じ色**を使う。

## 7. 実演（アニメーション）仕様

### 7.1 方式
ステージデータの `events` 配列を**先頭から順に非同期再生**するイベントランナーを実装（インタプリタは作らない。手書きイベント＋検証スクリプトで正しさを担保）。

### 7.2 イベント種別
| type | 引数 | 動作 |
|---|---|---|
| `line` | `n` | 疑似コードの n 行目をハイライト |
| `move` | `dir` | 1マス移動（移動絵＋バウンド） |
| `moveTo` | `x, y` | 経路探索して目的セルまで歩く（壁を避ける。経路は事前計算、データに`path`を書いてもよい） |
| `spawnItem` | `id, value, x, y` | 値クリスタルを出現させる |
| `pickup` | `id` | 拾う（クリスタルを頭上に） |
| `takeCopy` | `box, id` | ボックスの中身のコピーを取り出す（元の値は残る） |
| `put` | `id, target` | 計算台/比較台/配列セル/一時置き場に置く |
| `calc` | `expr, result, id` | 計算台で合体して結果クリスタルになる |
| `compare` | `expr, result` | 比較台に並べて判定（ランプが点灯） |
| `store` | `id, box` | ボックス/配列セルに入れる。古い値は飛び出して消え、値が更新される |
| `setCell` | `array, index, value` | 配列セルの状態をまとめて更新（交換などの内部処理で使用） |
| `toggle` | `target` | スイッチ/扉の切替 |
| `emote` | `"think"/"cheer"/"confused"` | エフェクト付き状態 |
| `push` / `pop` / `enqueue` / `dequeue` | `value` | スタック/キュー部品の操作演出 |
| `call` / `return` | `label, args, value` | 再帰の呼び出し/戻り演出（§10.9 参照） |
| `visit` | `x, y` | 探索・迷路で「訪問済み」マークを付ける |
| `wait` | `ms` | 待機 |
| `end` | — | 実演終了（最終位置・変数の確定） |
| `success` | — | 作業成功。アルゴくん cheer ＋ 検算マークが緑に光る（直後に ○＋ピンポン） |
| `fail` | `kind, reason` | 作業失敗。`kind`: `wall`（壁にぶつかってポヨン）/ `lock`（ボックスのロックが赤く光り値がはじかれる）/ `noGoal`（扉が開かない・旗がしぼむ）/ `mismatch`（検算マークが赤く点滅）。`reason` は吹き出しの短い一言。アルゴくん confused（直後に ×＋ぶっぶー） |

### 7.3 回答後の再生内容（選んだ選択肢のとおりに動く）
- 回答すると、**選んだ選択肢の内容どおり**にアルゴくんが動く。各選択肢が自分の `events` を持つ（正解は `stage.events` と同一でよい）。
- **正解**：動きが最後まで成功（末尾 `success`）→ 効果音「ピンポン」＋全画面○。
- **誤答**：その選択肢の動きを再現していき、途中または最後で作業に**失敗**（末尾 `fail`）→ 効果音「ぶっぶー」＋全画面×。
- **「検算」の考え方**（答えを見せてしまわないため、ゴール旗などで正解位置を事前に示さない）：
  - 位置を問う → 選んだ位置へ歩いたあと、**検算マーク**（虫眼鏡/チェック台）が出て、実際の結果と照合。一致なら緑に光る、不一致なら赤く点滅（`mismatch`）。途中で壁に当たる等なら `wall`。
  - 値を問う → 選んだ値のクリスタルを持ってきて、**検算ロック付きのボックス**に入れようとする。正しければロックが開いて入る、違えば赤く光ってはじかれる（`lock`）。
  - 順序・配列・回数を問う → その順/その状態になるよう操作し、最後に検算マークで照合。
- **解説画面**では、選択に関係なく「正しい処理」（`stage.events`）を再生する。

### 7.4 速度・スキップ
- 実演中は、フィールド直下（スマホでは sticky の上部）に **[⏩ 2倍速] [⏭ スキップ]** ボタンを表示する。
- **2倍速**：トグル。ON中は全アニメーション時間と待機を1/2にする（移動700→350ms。バウンド回数は維持）。実演の途中でもON/OFFでき、設定として保存される。
- **スキップ**：押すと、その実演を**最終状態まで即座に進める**（途中のアニメは省略し、位置・変数・配列を最終状態に確定）。**スキップしても判定演出（○/× と効果音）は必ず再生する**（結果が分からなくならないように）。誤答の選択肢をスキップした場合は、失敗状態の盤面 → ×＋ぶっぶー。
- 誤タップ防止のため、**画面タップだけではスキップしない**（ボタンのみ）。実演開始から0.3秒間はスキップを受け付けない。
- 解説画面の再実演にも同じボタンを表示する。

### 7.5 効果音（`engine/audio.js`、Web Audio API でコード生成。音源ファイルは使わない）
- `playSE(name)` を提供。`AudioContext` はタイトル画面の最初のタップで `resume()`。設定でミュート/音量変更。
- **`correct`（ピンポン）**：高い音→少し低い音の2音の鐘のような音。目安：E6(≈1319Hz) 150ms → C6(≈1047Hz) 450ms、sine＋軽い倍音、各音は指数減衰。
- **`wrong`（ぶっぶー）**：低いブザーを2回。目安：sawtooth 約150Hz を 0.18秒 →休符0.08秒→ 約140Hz を 0.45秒、lowpass 1200Hz 程度でマイルドに（耳に痛くしない）。gain は最大0.25×音量設定。
- 任意だが実装を推奨：`pickup`（ポッ）、`store`（コトッ＋小さなキラ）、`step`（移動の軽いポン。2倍速時は間引く）、`clear`（短いファンファーレ）。
- `correct`/`wrong` の開始時は他のSEを止め、重ならないようにする。ミュート時は音なしで、○×などの視覚演出だけ行う。

### 9.3 選択肢の「疑似コード表現(`code`)」の書き方ルール
- **位置を問う**：`(x, y) = (+1, −1)`（スタートからの相対）。または絶対座標 `(x, y) = (3, 2)`（ステージ内で統一）。
- **値を問う**：`x = 4` / `x = 4, y = 5`
- **配列の状態**：`a = [3, 1, 2]`
- **順序を問う**：`3 → 1 → 2`（訪問順・取り出し順）
- **回数を問う**：`3 回`
- **条件の真偽・分岐先**：`真（上へ進む）` / `偽（下へ進む）`
- 日本語表現(`ja`)は同じ内容を**自然な日本語の文**で書く。内容は`code`と**必ず同値**。

### 9.3b 選択肢ごとの演出（events）と失敗理由
各**不正解**の選択肢は、自分の動き（`events`）と失敗の種類を持つ。

```js
{ ja: "スタートから 右に2マス、上に1マス", code: "(x, y) = (+2, −1)",
  wrongFeedback: "3行目の「左へ1マス」を見落としていませんか？",
  events: [
    { type: "move", dir: "right" }, { type: "move", dir: "right" }, { type: "move", dir: "up" },
    { type: "fail", kind: "mismatch", reason: "あれ？ けんざんが あわない…" }
  ] }
```
- 正解の選択肢は `correct: true` のみでよい（省略時は `stage.events` ＋ `success` を使う）。
- 不正解の `events` は、**その選択肢が示す結果に至る動き**を再現する（例：「右に2・上に1」を選んだなら実際にその位置へ歩く）。壁を越えない。
- 末尾は必ず `fail`。`kind` は §7.2 の4種から、選択肢の内容に自然なものを選ぶ。`reason` は吹き出しで出す短い一言（ひらがな多め）。
- 検算の見せ方は §7.3 に従う（正解位置を事前に示さない）。

### 9.4 データ検証（必須）
`node tools/validate-stages.mjs` で全ステージを検査し、エラーなら非ゼロ終了：
- `choices` がちょうど4つで `correct: true` が1つ。全選択肢に `ja` と `code` がある
- 不正解の選択肢すべてに `wrongFeedback`
- 不正解の選択肢すべてに `events` があり、**末尾が `fail`（`kind` と `reason` 付き）**で、壁を越えない
- 不正解の `events` の最終状態が `expectedFinal` と**一致しない**（一致していたらエラー）
- 正解の `events`（省略時は `stage.events`）の最終状態が `expectedFinal` と一致する
- `program.ja` と `program.code` の**行数が一致**
- `events` を実際に空シミュレーションし、壁にぶつからず `end` に到達
- `events` が参照する `line` が `program` の範囲内
- `expectedFinal` と、イベント実行後の最終位置・変数・配列が一致
- 正解選択肢の `code` が `expectedFinal` の値と矛盾しない（自動照合できる形式のものは照合）
- `trace` の行が範囲内

## 10. ステージ設計（9ジャンル × 5レベル = 45ステージ）

### 10.0 難易度の定義（全ジャンル共通）
| Lv | 名前 | 目安 |
|---|---|---|
| 1 | 入門 | 1〜3行。用語なしで直感的に分かる。ジャンルの超短い導入つき |
| 2 | かんたん | 3〜6行。1つの概念を正しく適用 |
| 3 | ふつう | 6〜10行。2つの値/条件の追跡、境界値の気づき |
| 4 | ややむずかしい | 8〜14行。複数の概念の組み合わせ、見落としやすい罠（境界・初期値・更新順） |
| 5 | むずかしい | **基本情報技術者試験・科目Bで出題されうるレベル**。12〜20行程度。ループ＋配列＋条件の組み合わせ、変数の追跡表が必要なもの |

- **各ジャンルでLv1が簡単、Lv5が試験相当**であること。「全ジャンルのLv5が同程度に難しい」ように調整し、「ジャンルによって全部簡単/全部難しい」にならないよう作る。
- Lv5は選択肢の誤答が「よくあるミス（1つずれ、更新順の取り違え、初期値の見落とし）」から作られていること。
- 難易度が上がるにつれ、`program` の行数・変数の数・フィールドの要素が増える。

### 10.1 ジャンル一覧
| # | キー | ジャンル | 扱う内容 |
|---|---|---|---|
| ① | `var` | じゅんじょと へんすう | 順次実行、代入、変数の更新、値の交換 |
| ② | `cond` | わかれみち | 条件分岐（if / else if / else）、複合条件（かつ・または） |
| ③ | `loop` | ぐるぐる まわる | for / while、回数、ループ変数、合計・カウント |
| ④ | `arr` | ならんだ ぼっくす | 配列の添字、読み書き、合計・最大最小 |
| ⑤ | `search` | さがせ！ | 線形探索、番兵、二分探索（比較回数・探索範囲の追跡） |
| ⑥ | `sort` | ならびかえ | 交換、選択ソート、バブルソート、挿入ソート（途中経過） |
| ⑦ | `stack` | つみかさね・ならぶ | スタック（後入れ先出し）、キュー（先入れ先出し）、組み合わせ |
| ⑧ | `rec` | くりかえし よびだす | 再帰（階乗、フィボナッチ、べき乗、再帰とループの対応） |
| ⑨ | `maze` | めいろ | 迷路・経路（右手法、深さ優先探索、幅優先探索の訪問順、最短手数） |

> 添字は**1始まり**で統一（ステージ冒頭や配列の見た目に「1,2,3…」の添字を必ず表示）。

### 10.2 ジャンル別・レベル別の出題イメージ

**① var（じゅんじょと へんすう）**
- Lv1：右・上へ移動した最終位置
- Lv2：`x←3; y←x+2` の値
- Lv3：`x←x+y; y←x−y; x←x−y`（値の入れ替えの途中経過）
- Lv4：3変数の更新順（更新順を変えると結果が変わる）
- Lv5：変数5個以上の追跡表、代入の更新順の罠（前の値を使うか新しい値か）

**② cond（わかれみち）**
- Lv1：`もし x ≧ 5 ならば` の2方向
- Lv2：if / else if / else の3方向
- Lv3：複合条件（かつ・または）で到達するゴールを選ぶ
- Lv4：入れ子のif＋変数の更新を伴う分岐
- Lv5：複数の分岐＋ループ風の状態更新、条件の抜け漏れ（境界値 `≧` と `＞`）を見抜く

**③ loop（ぐるぐる まわる）**
- Lv1：`3回 右へ1マス` の最終位置
- Lv2：`i を 1 から 5 まで` の合計
- Lv3：while で条件が変わるまでの回数、奇数のみ加算
- Lv4：二重ループ（外側/内側の回数）、途中で `break` 相当の抜け
- Lv5：二重ループ＋条件＋配列への書き込み、ループ変数の最終値・回数の厳密な追跡

**④ arr（ならんだ ぼっくす）**
- Lv1：`a[2]` の値を読む
- Lv2：`a[2] ← a[1] + a[3]`
- Lv3：配列の合計、最大値を求めるループ
- Lv4：添字がループ変数・変数で変わる書き込み（`a[i] ← a[i−1] + 1`）
- Lv5：配列の要素を条件付きで集計・コピーして別配列に格納し、最終状態を問う（1つずれ注意）

**⑤ search（さがせ！）**
- Lv1：3つの箱から目的の値を探す（順番に開ける）
- Lv2：線形探索で見つかるまでの比較回数
- Lv3：見つからない場合の戻り値（`−1` など）、番兵の考え方
- Lv4：二重の条件を含む探索、最初/最後に見つかった位置
- Lv5：**二分探索**（`low, high, mid` の追跡、比較回数・最終位置）。mid の計算は切り捨て

**⑥ sort（ならびかえ）**
- Lv1：2つの値の交換（tmpボックスを使う）
- Lv2：3要素の簡単な並べ替えの1回目の結果
- Lv3：選択ソートの途中経過（k回目終了後の配列）
- Lv4：バブルソートの途中経過、交換回数
- Lv5：挿入ソート/バブルソートの**特定パス終了後の配列**と比較・交換回数の厳密な追跡

**⑦ stack（つみかさね・ならぶ）**
- Lv1：スタックにpush→pop（取り出す値）
- Lv2：キューのenqueue/dequeueの順序
- Lv3：push/popの混在、最後に残る要素
- Lv4：スタックとキューの比較（同じ入力で出力順の違い）、逆順出力
- Lv5：スタックを使った処理（括弧の対応チェック、逆ポーランド記法の計算など）の最終結果や途中状態

**⑧ rec（くりかえし よびだす）**
- Lv1：`f(n)` が `n = 1` で終わる簡単な再帰（呼び出し段数）
- Lv2：階乗 `f(3)`
- Lv3：和 `s(n) = n + s(n−1)`、戻り値の追跡
- Lv4：フィボナッチ `fib(4)` の呼び出し回数/値
- Lv5：2つの再帰呼び出しを含む処理や、引数が変化する再帰（最大公約数のユークリッド互除法など）の戻り値と呼び出し順

**⑨ maze（めいろ）**
- Lv1：1本道の迷路で、指示通り進むとどこへ着くか
- Lv2：分かれ道つき迷路で、右手法の通る順
- Lv3：行き止まりで戻る処理（バックトラック）の位置
- Lv4：深さ優先探索（DFS）の訪問順（優先方向：上→右→下→左などを問題で指定）
- Lv5：幅優先探索（BFS）の訪問順/最短手数、または DFS と BFS の訪問順の違い

### 10.3 ジャンル別のフィールド表現
- 変数ボックス・計算台を使うジャンル（①②③）：§6のボックス運びを毎回見せる。
- ④⑤⑥：配列を**横一列のセル（添字付き）**としてフィールド上に配置。値クリスタルをセルに運ぶ。交換は tmp ボックスを経由。
- ⑦：スタックは**縦に積む筒**、キューは**横の通路（入口と出口）**を描き、アルゴくんがクリスタルを積んだり並べたりする。
- ⑧：呼び出しごとに**階段/扉でフロアが深くなる**表現（`call`で下の階へ、`return`で値を持って上の階へ戻る）。深さは画面左に積んだカード（`f(3) → f(2) → f(1)`）としても表示。
- ⑨：マス目の迷路。`visit` で訪問済みマスの色が付き、訪問順番号が出る。

### 10.4 疑似コード記法（独自・科目Bの雰囲気を参考、日本語表現と対応）
| 疑似コード | 日本語表現 |
|---|---|
| `x ← 5` | x に 5 を入れる |
| `y ← x + 2` | x に 2 を足した値を y に入れる |
| `x ← x + 1` | x を 1 増やす |
| `もし x ≧ 5 ならば … そうでなければ …` | もし x が 5 以上なら…、そうでなければ… |
| `i を 1 から 3 まで 1 ずつ増やしながら繰り返す` | i を 1 から 3 まで 1 ずつ増やしながら繰り返す |
| `x < 10 の間、繰り返す` | x が 10 未満の間、繰り返す |
| `a[1]` | 配列 a の 1 番目 |
| `右(2)` | 右へ 2マス 進む |
| `push(3)` / `pop()` | スタックに 3 を積む／スタックから取り出す |
| `enqueue(3)` / `dequeue()` | キューに 3 を並べる／キューから取り出す |
| `f(n)` を再帰呼び出し | n を引数に自分自身を呼び出す |
- `program.ja` と `program.code` は**1対1の行対応**。インデントも揃える。
- 日本語表現は、どちらを見ても**同じ処理**だと分かる自然な日本語にする。

### 10.5 実装順の指示
1. **MVPは §11 の3ステージ**（`var-1`, `var-2`, `cond-1`）で、全機能（画像キャラ、ボックス運び、日本語/疑似コード切替、PC左右分割、スマホ縦）を成立させる。
2. MVP後、**ジャンル単位**で5レベルずつ追加し、毎回 `validate-stages.mjs` を通す。追加順：③loop → ② cond（残りLv2〜5）→ ① var（残りLv3〜5）→ ④arr → ⑤search → ⑥sort → ⑦stack → ⑧rec → ⑨maze。
3. 各ステージに必ず `hints`×3、`explanation`（`why`, `trace`, `points`）を付ける。問題はすべてオリジナル。
4. 各ジャンルを書き終えたら、**Lv1〜Lv5で難易度が単調に上がっているか**を見直し、不自然なら調整する（`DECISIONS.md`に記録）。

## 11. MVP サンプルステージ（詳細）

### var-1「みぎへ ひだりへ」（Lv1）
- フィールド7×5。start=(1,3) 向き=右。変数なし。
- program.ja：`右へ 2マス 進む` / `上へ 1マス 進む` / `左へ 1マス 進む`
- program.code：`右(2)` / `上(1)` / `左(1)`
- question：「この処理を実行したあと、アルゴくんはどこにいますか？」
- choices（ja / code）：**正：スタートから右に1マス、上に1マス / `(x, y) = (+1, −1)`**、右に2・上に1 / `(+2, −1)`、右に1 / `(+1, 0)`、スタートにもどる / `(0, 0)`
- events：各行 `line` → `move`、最後に `end`。移動は移動絵のバウンド。このステージは**ゴール旗を置かない**（答えの位置が分かってしまうため）。
- 不正解の演出：各選択肢の位置へ歩いたあと検算マークが赤く点滅（`fail` / `mismatch`）。例：「右に2・上に1」→ 3マス歩いて「あれ？ けんざんが あわない…」。「スタートにもどる」→ 右・上・左と歩いて元の位置へ戻り、同じく不一致。
- trace：`1行目: (3,3)` / `2行目: (3,2)` / `3行目: (2,2)`

### var-2「ぼっくすに いれよう」（Lv2）
- フィールド7×5。左にクリスタル出現場所、右に**変数ボックス x（水色）・y（緑）**、中央に**計算台**。
- program.ja：
  1. `x に 3 を入れる`
  2. `x に 2 を足した値を y に入れる`
  3. `y から 1 を引いた値を x に入れる`
- program.code：`x ← 3` / `y ← x + 2` / `x ← y − 1`
- question：「処理が終わったとき、x の値はいくつですか？」
- choices：`3`（`x = 3`）／**`4`（`x = 4`）**／`5`（`x = 5`）／`7`（`x = 7`）。各 `ja` は「x は 3 です」等、`code` は `x = 3` 等。
- events（§6の演出に従う）：
  - 1行目：`spawnItem(3)` → `moveTo` → `pickup` → `moveTo(ボックスx)`（carry）→ `store(x)`
  - 2行目：`takeCopy(x)` → `put(計算台)` → `spawnItem(2)` → `pickup` → `put(計算台)` → `calc(x+2=5)` → `pickup(結果)` → `moveTo(ボックスy)` → `store(y)`
  - 3行目：`takeCopy(y)` → 計算台で `calc(y−1=4)` → `moveTo(ボックスx)` → `store(x)`（x の古い値3がポンと飛び出して消え、4が入る）
- trace：`1行目: x=3` / `2行目: x=3, y=5` / `3行目: x=4, y=5`
- 不正解の演出：「`5`」を選ぶと、アルゴくんは y のクリスタル(5)を持って x のボックスへ運ぶが、**ボックスのロックが赤く光って値がはじかれる**（`fail` / `lock`、「ロックが あかない…」）。他の誤答も同様に、その値を x に入れようとして失敗する。
- wrongFeedback例：「`3`」→「3行目で x が上書きされます」、「`5`」→「5 は y の値です。x は 3行目で更新されます」、「`7`」→「足し算を重ねていませんか？ 3行目は引き算です」
- points：「代入は右辺を先に計算して、左辺に入れる」「入れた値は古い値を置き換える」

### cond-1「わかれみち」（Lv1）
- フィールド：T字路。左がスタート、分岐して上と下にゴール。**変数ボックス x（初期値7）**がスタート付近にある。
- program.ja：`もし x が 5 以上なら` / `　上へ 1マス 進む` / `そうでなければ` / `　下へ 1マス 進む` / `右へ 2マス 進む`
- program.code：`もし x ≧ 5 ならば` / `　上(1)` / `そうでなければ` / `　下(1)` / `右(2)`
- events：`line(1)` → `takeCopy(x)` → `put(比較台)`＋「5」クリスタルも並べて `compare(7 ≧ 5 = 真)`（ランプが緑）→ 上へ → `右(2)`
- choices：**正：スタートから右に2マス、上に1マス / `(x, y) = (+2, −1)`**、下に1・右に2 / `(+2, +1)`、右に2のみ / `(+2, 0)`、上に1のみ / `(0, −1)`
- 不正解の演出：「下に1・右に2」を選ぶと、実際に下へ歩いたあと検算マークが赤く点滅（`fail` / `mismatch`）。「右に2のみ」「上に1のみ」は途中までしか動かず、検算で不一致。※このステージはゴール旗を置かない（答えの位置が分かるため）。
- wrongFeedback例：「下へ」→「x は 7 なので、条件 x ≧ 5 は成り立ちます」
- points：「条件が真のときだけ if 側が実行される」「分岐のあとの処理は両方の場合に実行される」
